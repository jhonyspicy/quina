# 時計ロジック（`@quina/clock`）

トーナメントクロックの状態と、そこから表示用の値を計算する純粋関数のパッケージ。実装は `packages/clock/src/clock.ts`。通信・保存・画面描画は扱わない。

要件は[大会単位のリモコン・サイネージ接続と進行操作](../../openspec/changes/tournament-remote-signage/spec.md)の「待機・受付・開始」「現在の残り時間」に対応する。大会状態の管理元は大会ごとのDurable Objectとする方針（[ADR 0004](../adr/0004-cloudflare-durable-objects-and-initial-stack.md)）で、本パッケージは `apps/api` の大会のDurable Objectと、`apps/remote`・`apps/signage` の双方から使う（[大会の接続と同期](realtime.md)）。

## 状態は基準だけを持つ

時計の状態（`ClockState`）は、毎秒変わる値ではなく計算の基準だけを持つ。

| 状態 | 持つ値 |
| --- | --- |
| `waiting`（待機中） | なし |
| `running`（進行中） | 現在レベル、`anchoredAt` 時点の残り時間、`anchoredAt`（基準時刻） |
| `paused`（一時停止中） | 現在レベル、残り時間 |

表示する値（`ClockView`）は `getClockView(state, structure, now)` で現在時刻から計算する。基準時刻からの経過時間を残り時間から引き、使い切ったレベルは次へ進める。表示端末は、受信した状態があれば通信が途切れても時計を進められ、一時停止の状態なら進まない。

時刻はすべてUNIXエポックからのミリ秒を引数で受け取り、関数内で現在時刻を読まない。管理元と表示端末の時刻のずれの補正は本パッケージの対象外で、未決定。

## ストラクチャー

`Structure` はレベルの配列で、現在は各レベルの長さ（`durationMs`、正の整数）だけを持つ。ブラインド金額や休憩などの項目は未実装。レベルが空、または長さが正の整数でない場合は `RangeError` とする。

## 操作

操作は現在の状態と現在時刻を受け取り、新しい状態を返す。対象外の状態では受け取った状態をそのまま返す。

| 操作 | 有効な状態 | 結果 |
| --- | --- | --- |
| `start` | 待機中 | 最初のレベルの長さで進行を始める。開始済みの状態に届いた開始では時計をリセットしない |
| `pause` | 進行中 | その時点のレベルと残り時間を保持して停止する |
| `resume` | 一時停止中 | 保持した残り時間から進行を再開する |
| `setRemaining` | 進行中・一時停止中 | 現在レベルの残り時間を置き換える。進行中ならそこから進み、一時停止中なら停止を保つ。ストラクチャーのレベル時間は変えない。負の値・整数でない値は `RangeError` |

予定時刻による自動開始の仕組みはなく、`start` を呼ぶまで待機を続ける。

## 最終レベルの扱い

最終レベルの時間を使い切ると、最終レベルのまま残り時間を0とし、`ClockView.finished` を `true` にする。状態は進行中のままで、大会終了の扱いは決めていない。

## 残り時間の表示

`formatRemaining` は残り時間を `分:秒`（1時間以上は `時:分:秒`）の文字列にする。秒未満は切り上げ、残り0.2秒は `0:01` と表示し、`0:00` になるのは残り時間を使い切ったときだけとする。
