## 変更の目的と範囲

店舗が大会を準備し、複数スタッフのスマホと複数の表示端末を接続して、受付から大会進行・撮影用表示まで扱うための変更仕様。スタッフの操作中もプレイヤー向け表示を保ち、小店舗の2〜3台のモニターや、同店舗での複数大会の同時進行に対応したい。

最初の実装候補は、接続・待機中の受付・開始と一時停止／再開・現在残り時間の変更・同期・操作履歴を通して使える範囲とする。これは実装順序の候補であり、ユーザー登録、店舗課金、柔軟なエントリーチップ数、アドオン、テーマ、入賞・優勝演出などを含む既存の初回リリース全体を置き換えない。記録時点ではアプリ実装・デプロイや技術選定を行っていない。技術選定は後日[ADR 0004](../../../docs/adr/0004-cloudflare-durable-objects-and-initial-stack.md)で採用した。

### 試作版との関係

別プロジェクト `poker-blind-timer` は三店舗で利用されている試作版で、タイマー計算、リモコン、Ably通信、IndexedDB、テーマ・優勝演出があるという会話上の背景を持つ。これはQuinaでの実装実績ではない。本記録のために試作版コードの検証は行っていない。

試作版の一括移植は決定していない。Quinaの土台を新しく設計し、独立したロジックや演出を選択的に再利用する案は提案段階。Ablyは[ADR 0004](../../../docs/adr/0004-cloudflare-durable-objects-and-initial-stack.md)により採用しない。IndexedDBの利用有無は決定していない。

## 合意した要件

### 大会の準備とスタッフ接続

- 店舗管理画面で大会を選択して準備し、スタッフ接続用QRコードを表示する。この操作では時計を開始しない。
- 各スタッフが同じQRコードをスマホで読み取ると、その大会のリモコンになる。スマホ側でスタッフにログインを要求する手間を避ける。管理画面側の認証詳細は未決定。
- 全スタッフのリモコンは同じ操作権限を持つ。専用スタッフロールや人物認証の追加を決定したものではない。
- 一大会に複数リモコン・複数表示端末を接続できる。各表示端末が同じPCにつながっていることを前提にしない。
- 同店舗の複数大会の同時進行を初回対応の対象とする。時計・人数・履歴は大会単位で分ける。
- 同時実行数は店舗ごとのプランで制限する。フリーは同時1大会、プロは複数大会とする。プロの具体的な上限は未決定であり、無制限とは決定していない。待機受付中・撮影画面中を数に含めるかは未決定。
- リモコンはQRで接続した大会を操作する。リモコン内で複数大会を切り替える機能は不要。

### 表示端末の接続

- 未接続の表示端末でサイネージURLを開くと、六桁PINを表示する。
- スマホの「サイネージに接続」相当の操作からPINを入力すると、その表示端末がスマホの接続先大会の表示になる。
- PINの表示は接続前だけとし、一度接続に使ったPINは無効にする。同じPINを別大会から入力して接続先を乗り換えることはできない。
- 接続済み表示端末のページ再読み込みでは、同じ大会の最新状態へ復帰する方針を継続する。ユーザーから難しければPINに戻してもよいとの許容はあったが、復元案の説明後も同大会への復帰を目指している。具体的な保存方式は未決定。

### リモコンの識別と操作履歴

- リモコンには大会ごとに `1`、`2`、`3` などの識別番号を付ける。別大会では振り直す。
- 同大会内の同一スマホブラウザでは、再読み込みや一時的な通信切断からの再接続でも同じ番号を保つ。これは端末の識別であり、人の本人確認ではない。
- エントリーに限らず、どの操作をどの端末が行ったかを履歴で確認できる。各スタッフは同大会の全リモコンの操作履歴を閲覧できる。
- 別端末が追加したエントリーも他リモコンから取り消せる。元の追加操作と取り消し操作、それぞれを行った端末の両方を履歴に残す。
- あらゆる操作を取り消す汎用undoまで合意したものではない。

### 同期と通信切断

- スマホの通信切断中は、そのスマホから操作できない。進行中の大会の時計は継続し、スマホは再接続時に最新状態へ復帰する。オフライン操作をためて後送する仕様は採用していない。
- 二台が独立して一件ずつエントリー追加を行った場合は合計二件となる。同じ操作の通信再送では重複計上しない。
- 表示端末の通信切断中は、受信済み情報をもとに時計を進め、「接続切れ」を表示する。受信済み状態が一時停止なら勝手に進めない。
- 表示端末は切断中に他端末の停止・変更を受信できない。復帰時に最新状態へ同期する。切断中も最新の停止・変更が反映されることは保証しない。

### 待機・受付・開始

- 大会開始前は待機画面を表示する。受付スタッフがリモコンでエントリーを追加すると、登録人数を同大会の各待機画面へ反映する。
- 予定時刻に達しても自動開始しない。ディーラーとプレイヤーの準備後、スタッフがリモコンから明示的に開始すると、接続中の全表示がタイマー表示に切り替わり時計が始まる。
- 開始操作は試作版と同様の「スライドして開始」とする。一回のタップや確認ダイアログによる開始ではない。一時停止・再開は通常のボタンで行う。
- 大会開始後もエントリーを追加できる。レイトレジスト締切後も追加でき、締切を理由に操作を止めない。締切後の確認ダイアログは合意しておらず、必須化しない。

### 現在の残り時間

- リモコンで現在残り10分を残り1分に設定した場合、同大会の接続中の全表示も残り1分となり、進行中ならそこから進む。
- 一時停止中の残り時間変更は、停止状態を保ったまま各表示に反映する。
- 現在の残り時間の変更と、ストラクチャーに設定したレベル時間の編集は別の操作・要件として扱う。

### 優勝演出・記念撮影

- 優勝演出・記念撮影用表示は、スタッフが明示的に終了するまで残す。
- 撮影用表示を終える操作はスマホから行える。
- 大会終了／撮影終了に伴う接続解除や、その後の表示・次大会への移行は未決定。

## 希望する対応と詳細未決定の範囲

### Google TV

表示端末はPCブラウザに加えGoogle TVアプリも想定する。テレビ対応はGoogle TVのみとし、初回リリースの必須条件ではないが、できるだけ早期のリリースを希望している。テレビのリモコンで操作する前提を考慮し、PC・マウス必須の運用にしない。Google TV向けの実装方式や具体的な提供時期は未決定。

### 大会開始後のストラクチャー編集

大会開始後もブラインド金額・各レベル時間を変更したいという希望がある。ただし、設定時間を変えた際の経過時間・現在残り時間の計算、現在レベルや将来レベルへの適用は未決定。本仕様の「残り10分を1分にする」という合意から、ストラクチャー編集時の計算方式を導かない。

## 採用した設計

- 進行中の大会状態は、大会ごとのCloudflare Durable Objectを唯一の正とする。リモコンとサイネージは自分の大会のDOにWebSocketで接続し、DOが状態を配信する。表示端末は受信した時計の基準から毎秒の表示を計算する。店舗・アカウント・契約など大会をまたぐデータはCloudflare D1で管理する。判断と理由、技術構成は[ADR 0004](../../../docs/adr/0004-cloudflare-durable-objects-and-initial-stack.md)を参照する。

## 設計案（採用未確定）

- 複数端末から開始が届いても一度だけ開始し、後着の開始で時計をリセットしない案。説明済みの設計案として記録し、合意済み受け入れ条件と分ける。時計ロジック（`@quina/clock`）の `start` はこの案に沿い、待機中以外では状態を変えない実装とした。
- 表示端末のブラウザ情報が失われた場合や接続解除時には、PIN画面へ戻す案。
- スマホのモニター一覧から解除する案と、表示側から解除して新しいPINを表示する案。どちらに置くか、両方提供するか、大会終了に連動するかは未確定。

## 受け入れ条件

以下は合意した要件を将来の実装時に確認する条件であり、検証済みではない。設計案の採否や詳細未決定のストラクチャー編集を、この表で確定しない。

| 条件・操作 | 期待する結果 |
| --- | --- |
| 管理画面で大会を選択・準備しQRを表示 | 時計は開始しない |
| 複数スタッフが同じQRをスマホで読む | スマホ側のログイン要求なしに同大会のリモコンとなり、同じ操作権限を持つ |
| 独立した複数表示端末がそれぞれサイネージURLを開く | 未接続端末に六桁PINを表示し、それぞれを同大会へ接続できる |
| リモコンで表示端末のPINを入力 | その大会の表示となり、PIN表示を終了し、使用済みPINを無効にする |
| 別大会のリモコンから使用済みPINを入力 | 接続済み端末を別大会へ乗り換えさせない |
| 接続済み表示端末を再読み込み | 接続情報を保持できている場合、同大会の最新状態へ復帰する。情報消失時の扱いは別途決定する |
| フリー店舗ですでに1大会を実行中に、別大会も実行しようとする | 同時実行を1大会に制限する。待機受付中・撮影画面中の算入や制限時のUIは別途決定する |
| プロ店舗で複数大会を同時実行 | 複数大会を実行できる。具体的な上限は別途決定し、無制限を前提にしない |
| 同じ管理者のフリー店舗とプロ店舗で大会を実行 | 店舗ごとにプランの同時実行数制限を適用する |
| プロ店舗の大会A・Bを同時進行し、Aの人数・時計を操作 | Bの人数・時計・履歴にAの操作を混在させない |
| 同大会でスマホを再読み込み／一時切断後に再接続 | 同一ブラウザのリモコン識別番号を維持する。別大会では大会ごとに振り直す |
| 複数リモコンからエントリー追加や時計操作を実施 | どの端末がどの操作をしたかを、同大会の各リモコンから履歴で確認できる |
| 端末1の追加エントリーを端末2で取り消す | 取り消せる。元の追加と取り消し、および両端末の識別を履歴に残す |
| 二台が独立して一件ずつエントリー追加 | 合計二件を計上する |
| 同じエントリー追加操作が通信で再送される | 一件だけ計上する |
| 進行中にスマホの通信が切れる | そのスマホは操作不可となるが、大会の時計は進行を続ける。復帰時に最新状態を表示する |
| 進行中の表示端末の通信が切れる | 受信済み情報で時計を進め「接続切れ」を表示し、復帰時に最新状態へ同期する |
| 一時停止を受信済みの表示端末の通信が切れる | 勝手に時計を進めず、「接続切れ」を表示する |
| 表示端末の切断中に別端末が停止・残り時間変更 | 切断端末では未受信の操作が反映されないが、再接続で最新状態に同期する |
| 開始前にエントリーを追加 | 同大会の各待機画面の登録人数に反映する |
| 開始予定時刻に達する | スタッフの明示開始まで待機を継続する |
| リモコンでスライドして開始 | 接続中の全表示をタイマーへ切り替え、時計を開始する |
| 通常ボタンで一時停止／再開 | 同大会の接続中の表示に停止／再開が反映される |
| 大会開始後、またはレイトレジスト締切後にエントリー追加 | 追加でき、締切を理由に拒否しない |
| 進行中の現在残り10分を1分へ変更 | 接続中の全表示で残り1分となり、そこから進行する |
| 一時停止中の現在残り時間を変更 | 接続中の全表示に変更を反映し、停止を維持する |
| 優勝演出・記念撮影用表示を表示後、スタッフが終了していない | 表示を維持する |
| スマホから撮影用表示を明示終了 | 撮影用表示を終了できる。終了後の画面や接続状態は別途決定する |

## 未決定事項

- 管理画面側の認証、店舗と管理者の詳細な権限関係。
- プロの同時実行数の具体的上限、待機受付中・撮影画面中を同時実行数に含めるか、制限時のUI。
- プロ利用期間終了時に進行中の複数大会をどう扱うか。時計の停止・大会終了・接続解除を自動で行うとは決定しない。
- スタッフ接続用QRの有効期間・失効・再発行などの接続管理。
- PINの発行方式、有効期限、未使用PINの競合・入力失敗時の扱い。
- リモコン内部IDの方式・保存寿命、ブラウザ情報消失時の識別番号の扱い。
- 表示端末の接続情報の保存・復元方式、情報消失時の復帰先。
- 接続解除UIの場所、スマホ側／表示側の両方を提供するか、終了操作との連動、新PINの発行方法。
- 操作の重複防止の具体方式、同期の許容遅延、競合操作の処理規則、表示端末と管理元の時刻のずれの補正方法。大会状態の管理元・通信基盤・永続化の基盤は[ADR 0004](../../../docs/adr/0004-cloudflare-durable-objects-and-initial-stack.md)で決定した。
- 店舗単位の同時実行数を数える具体方式（ADR 0004では、D1だけに頼らず店舗単位のDOなどで直列化する方針とした）。
- 未接続の表示端末がPINを表示している間の接続先。
- 履歴の詳細項目・保存期間・表示方法、エントリーの重複取り消しや競合時の扱い。汎用undoは合意範囲外。
- 開始後のブラインド金額・設定レベル時間の編集方法と適用範囲・経過時間計算。
- 大会終了と撮影終了の関係、終了後の表示、接続解除の有無、次大会への移行詳細。
- 最終レベルの時間を使い切った後の扱い。時計ロジックは現在、最終レベルのまま残り0で止め、終了状態の印を付ける（[時計ロジック](../../../docs/architecture/clock.md)）。
- Google TVアプリの実装方式・提供時期と、テレビリモコンによる具体的な操作導線。

## 既存方針との整合

大会単位で時計・人数・履歴を分けることは、契約・課金・クーポンの単位を大会やリモコンへ変えるものではない。[店舗単位の契約に関するADR](../../../docs/adr/0002-store-scoped-subscriptions.md)の一店舗一契約を維持する。

テーマ条件は関連仕様に従う。通常は指定店舗かつプロ利用期間中に専用テーマを利用でき、運営確認用の例外は明示指定された店舗だけに適用する。一店舗に複数専用テーマを紐づけられること、プロ利用期間終了後も無料の標準テーマでクロックを継続利用できることを変更しない。大会進行中にプロ期間が終了した場合のテーマ切替時期は既存仕様でも未決定であり、本仕様では決定しない。

今回の追加決定により、従来の「テーマだけでプラン差」という方針を変更し、店舗ごとの大会同時実行数にも差を設ける。複数リモコン・表示端末の台数について新たなプラン差は決定していない。テーマの運営確認用例外を同時実行数制限の例外へ拡張しない。プロ終了時の複数大会の扱いは、テーマ切替時期とともに未決定事項として残す。
